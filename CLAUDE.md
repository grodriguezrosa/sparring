# Sparring

App to prepare for IT job interviews with an AI-powered voice interviewer.
First interview language: Spanish. First user: the author himself (preparing for a Python/backend interview).

## Core idea

The user provides the **full job offer** and their **CV**. The whole interview is built from both:
questions come from what the offer asks for and what the CV says, and the evaluation is done against that offer's requirements.

## MVP flow

1. **Setup:** the user pastes the job offer text and uploads their CV (PDF or Word).
2. **Pre-analysis:** the LLM extracts a structured profile (stack, level, responsibilities, what the CV covers, gaps between CV and offer) and generates an interview plan.
3. **Voice interview** in Spanish: the interviewer speaks, listens, asks follow-up questions and changes topic depending on how it goes.
4. **Background scoring:** each answer is scored against a rubric derived from the offer; those scores decide whether to follow up or move on.
5. **Final report:** scores per criterion, fit with the offer (which requirements were demonstrated and which were not), detected mistakes, model answers and what to work on.

One job offer and one CV per session. Multiple offers/CVs per user is out of the MVP.

## Stack

| Layer | Technology |
|---|---|
| Frontend | Next.js on Vercel |
| Backend | FastAPI (Python) |
| Voice | ElevenLabs (conversational agent, direct browser-ElevenLabs connection) |
| Conversation | DeepSeek (questions, follow-ups, interview plan, report) |
| Scoring/decisions | Jev (`typesafe-ai/jev`, via Vercel AI Gateway) |
| Data | Managed PostgreSQL on **AWS (RDS)** or **Google Cloud (Cloud SQL)**, using their free offers. Learning cloud services is an explicit goal of the project. |

## Architecture

- Audio does NOT go through our backend. The browser connects to ElevenLabs with a signed token/URL generated by FastAPI.
- ElevenLabs uses DeepSeek as a custom model (OpenAI-compatible endpoint) for the conversation.
- FastAPI handles: job offer and CV analysis, interview plan, rubric, scoring, report, persistence.
- FastAPI runs in a container, not in Vercel serverless functions, because of long-lived connections. Preferably on the same cloud as the database (e.g. AWS App Runner/ECS or Google Cloud Run), to learn the platform end to end; Railway, Render or Fly.io remain fallbacks.
- Vercel hosts only the frontend.

## Commands

- `make check`: lint + format + mypy strict + tests. Must pass before considering any change done (CI runs the same).
- `make format`: formats and applies automatic fixes.
- `make dev`: development server.
- `make test-live`: tests marked `@pytest.mark.live` against real APIs (need `.env`, cost money; never in CI).
- `make preflight`: pre-publish checks for the checked-out branch (`scripts/preflight.py`): branch name (`<type>/<name>`, no direct pushes to `master`/`main`), no forbidden files (`.env`, `lessons/`, `CLAUDE.local.md`, keys), no secrets in any commit being pushed (known key formats and the values in `.env`), no files over 1 MB, clean working tree, `uv lock --check` and `make check`.
- `make hooks`: once per clone; sets `core.hooksPath=.githooks` so `git push` runs the preflight automatically. Skip only in an emergency with `git push --no-verify`.
- Voice interview in development (the agent needs a public URL for our custom LLM endpoint):
  1. `make dev` and, in another terminal, `make tunnel` (cloudflared quick tunnel; prints a new `https://*.trycloudflare.com` URL each time).
  2. `make agent-config URL=<tunnel URL>`: points the real ElevenLabs agent at it (`scripts/configure_agent.py`: backs up the agent to `backups/`, changes only the managed fields, verifies limits/voice/tools are unchanged; `--restore <backup>` undoes it).
  3. `make interview`: typed interview through the real agent (`scripts/text_interview.py`; uses one conversation of the agent's daily limit).
  Quick tunnels die after a while or a network pause ("Tunnel not found"): start a new one and run `make agent-config` again.

## Backend conventions

- Python 3.12+, FastAPI, Pydantic v2 for every input and output model.
- Language: everything in the repository is in English (code, API JSON fields, routes, tests, comments, docstrings, error messages, test data, docs, LLM prompts). The only Spanish part is the product's interview language: prompts explicitly instruct the LLM to write its output in Spanish.
- Dependency management with `uv` (`uv add <package>`, `uv add --dev <package>`). There is no `requirements.txt`.
- Tests with `pytest`. Every new endpoint gets at least one test.
- Configuration and keys via environment variables (`.env` kept out of version control). Never keys in the code.
- LLM calls are wrapped in their own module (`app/llm/`) so the provider can be swapped without touching the rest.
- Structured LLM outputs validated with Pydantic; on failure, retry once and return a clear error. Always use `app.llm.structured.generate_structured`.
- Tests without network: use `FakeLLM` or `httpx.MockTransport`. No real calls outside `live` tests.

## Security and privacy

- The CV and the job offer are **untrusted text**: they may contain instructions trying to manipulate the interviewer. They are always passed to the model as delimited data with `app.llm.untrusted.delimit()` (plus `UNTRUSTED_DATA_POLICY` in the system prompt), never as system instructions.
- The CV contains personal data (GDPR): store the minimum, inform the user and offer deletion at the end of the session.
- Never log CV contents or full transcripts.
- ElevenLabs and DeepSeek keys never reach the browser; only the signed session URL does (valid 15 min, single-use, served with `Cache-Control: no-store`, never logged in full). Always request it with `include_conversation_id=true`: a plain signed URL can be reused for 15 minutes and would bypass the voice quota. The adapter refuses a URL without `conversation_id` (ADR 0002).
- The ElevenLabs agent has authentication enabled, so it only accepts signed URLs. The ElevenLabs key is restricted to "ElevenLabs Agents = Write" (signed URLs require `convai_write`), everything else "No access".
- Cost protection, in layers:
  1. ElevenLabs agent limits (dashboard): concurrency 1, low daily conversation limit, max conversation duration 35 min (the default of 10 min would cut interviews short).
  2. Access codes: every paid endpoint (`/profile`, `/interview-plan`, `/voice-session`) requires the `X-Access-Code` header (`app/api/security.py`, codes in `ACCESS_CODES`, compared with `secrets.compare_digest`). `/health` stays open. Invite codes, not user accounts (those come in phase 2).
  3. Per-code daily quota for voice sessions (`app/services/quota.py`, 429 + `Retry-After`; refunded if the provider fails). In memory: valid for a single instance and reset on restart; it must move to Postgres before running more than one instance.
- Voice sessions: `POST /voice-session` receives the interview plan and stores `conversation_id -> plan` (`app/services/conversations.py`, in memory, 2 h TTL, same single-instance limits as the quota). The plan comes back from the client, so it is untrusted data like the CV it was built from: size-bounded on input, and always delimited when it is put into a prompt.
- Voice turns: the ElevenLabs agent uses `POST /v1/chat/completions` (`app/api/agent_llm.py`) as its custom LLM. It is authenticated with `AGENT_LLM_SECRET` as a Bearer token (not with access codes), finds the conversation through the `<conversation_id>{{system__conversation_id}}</conversation_id>` marker in the agent's stub prompt (`AGENT_PROMPT_STUB`), returns 404 for unknown conversations, replaces ElevenLabs' system prompt with ours (`app/services/interviewer.py`, plan delimited, scoring signals excluded) and streams DeepSeek's reply as OpenAI SSE chunks.

## Resolved decisions

Significant architecture decisions get a record in `docs/decisions/` (ADR format, see `docs/decisions/README.md`). Records are public: no keys, personal data or raw experiment output. Experiments (spikes) stay local in the git-excluded `spikes/` folder.

- **Jev from Python (Nov 2026): yes, from FastAPI over plain HTTP.** Vercel AI Gateway exposes `POST https://ai-gateway.vercel.sh/v1/decisions` (OpenAI-compatible Decisions API, `Authorization: Bearer $AI_GATEWAY_API_KEY`, model `typesafe-ai/jev`). Validated with a local spike, see `docs/decisions/0001-score-answers-with-jev.md`: sensible Spanish scores, injection did not inflate them, ~0.2-0.3 s latency, ~$0.00003 per request. No Next.js route or DeepSeek fallback needed.

## Open decisions

- **Reading the job offer from a URL:** many job boards (LinkedIn, InfoJobs) block it. In the MVP, pasted text only.
- **Cloud for the database: AWS or Google Cloud.** Neither offers a permanently free managed Postgres (checked Nov 2026):
  - AWS (accounts created after 15 Jul 2025): Free plan with $100 credits (+ up to $100 more), up to 6 months, never bills; the account closes when it ends unless upgraded. RDS for PostgreSQL on `db.t4g.micro` (~$12/month in credits), or Aurora PostgreSQL serverless (up to 4 ACU, 1 GiB, can pause when idle).
  - Google Cloud: no free tier for Cloud SQL. 30-day Cloud SQL trial instance + $300 credits for 90 days (credit card required). Afterwards the smallest instance (`db-f1-micro`) is billed (~$8/month + storage).
  - Whichever is chosen: an EU region (CVs are personal data under GDPR), a budget alert from day one, and the database is reached through a repository port so tests use an in-memory adapter and local development uses Postgres in Docker.
- **Quality in Spanish:** test DeepSeek and the ElevenLabs voice with real Spanish answers before trusting the scores.
