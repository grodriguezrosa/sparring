# Sparring · Backend

Backend for **Sparring**, an app to prepare for IT job interviews with an AI-powered voice interviewer that conducts the interview in Spanish.

The user provides **the job offer** and **their CV**. From both, the app:

1. Extracts a structured profile: stack, level, responsibilities and gaps between the CV and the offer.
2. Generates an interview plan.
3. Runs the voice interview: asks, listens and follows up.
4. Scores each answer against a rubric derived from the offer.
5. Delivers a final report: scores per criterion, fit with the offer, mistakes, model answers and what to work on.

This repository contains **only the backend** (FastAPI). The frontend (Next.js) lives in a separate repository.

> **Status:** work in progress (phase 0 of the [roadmap](ROADMAP.md)). The project foundation is in place (configuration, DeepSeek client, tests and CI); endpoints: `GET /health`, `POST /profile` (job offer + CV as text → structured profile) `POST /interview-plan` (profile → interview plan with topics, questions and time per topic) and `POST /voice-session` (signed URL for the browser to talk to the ElevenLabs agent).

## Architecture

```
Browser (Next.js) ──── audio ────► ElevenLabs ──► DeepSeek (conversation)
        │                              ▲
        │ HTTP                         │ signed token
        ▼                              │
   FastAPI (this repo) ────────────────┘
        │  job offer and CV analysis, plan, rubric, scoring, report
        ▼
     Postgres
```

- Audio does **not** go through this backend: the browser connects directly to ElevenLabs with a signed token generated by FastAPI.
- ElevenLabs and DeepSeek keys never reach the browser.
- The CV and the job offer are treated as **untrusted text**: they are passed to the model as delimited data, never as instructions.

| Layer | Technology |
|---|---|
| API | FastAPI (Python 3.12) |
| Voice | ElevenLabs (conversational agent) |
| Conversation | DeepSeek |
| Scoring | Jev, via Vercel AI Gateway (to be confirmed) |
| Data | Managed PostgreSQL on AWS (RDS) or Google Cloud (Cloud SQL), free offers (to be decided) |
| Deployment | Container, preferably on the same cloud as the database |

## Requirements

- [uv](https://docs.astral.sh/uv/). If you don't have Python 3.12, uv downloads it.

## Getting started

```bash
make install           # creates .venv and installs the exact versions from uv.lock
cp .env.example .env   # then fill in the keys
make dev               # development server with auto-reload
```

Every endpoint except `/health` requires an access code in the `X-Access-Code` header (one of the `ACCESS_CODES` in `.env`). In `/docs`, fill it in on each request.

With the server running:

- http://127.0.0.1:8000/health: checks that the API is alive.
- http://127.0.0.1:8000/docs: interactive API documentation.

## Checks

```bash
make check       # lint + format + types (mypy strict) + tests. Same as CI.
make format      # formats code and applies ruff's automatic fixes
make test-live   # tests against real APIs (needs .env and costs money)
```

Tests marked `live` call real APIs and are excluded by default from `make test` and from CI.
CI (GitHub Actions, `.github/workflows/ci.yml`) runs `make check` on every push and pull request.

Before publishing a branch, run the preflight checks (branch name, forbidden files, secrets in the pushed commits, clean tree, lock file and `make check`). Install the pre-push hook once per clone so `git push` runs them automatically:

```bash
make hooks       # git push now runs scripts/preflight.py first
make preflight   # run the same checks by hand
```


## Structure

```
app/
  main.py      creates the app and mounts the routers
  api/         endpoints (one file per topic, with APIRouter)
  services/    business logic: prompts and LLM orchestration
  schemas/     Pydantic input and output models
  config.py    configuration from environment variables (.env)
  llm/         LLM access: interface, DeepSeek, fake LLM, structured output, untrusted text
tests/         pytest tests
pyproject.toml dependencies and ruff, mypy and pytest configuration
uv.lock        exact versions (committed)
```

## Privacy

The CV contains personal data (GDPR). The minimum is stored, neither the CV nor full transcripts are logged, and deletion is offered at the end of the session.
